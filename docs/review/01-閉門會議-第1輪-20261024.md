### 1.1 `agent.py`

1. **有效內容**
   - 區段標頭用「【harness 角色：…】」（第 21、38、124、132、308、415、500、511、548、560、579、666、869 行）。讀者不用看程式就知道檔案怎麼分工，這是「理解深度」最便宜、最有效的證據。
   - 註解解釋**為什麼**而且附出處：`close_dangling` 的理由（API 對孤兒 `tool_use` 回 400）、`SESSION_SYSTEM` 凍結的理由（thinking 簽章綁定 system＋tools＋歷史，第 541–544 行，連到 v3 真實踩到的 400）、`read_file` 自己在行邊界停下而不是交給通用截斷（第 175–176 行）、`_clean_env` 擋 `ANTHROPIC_*`（第 246–248 行）。這些註解是讀過 log、踩過坑才寫得出來的。
   - 權限層的設計原則寫在程式裡（第 308–314 行）：「不列舉危險，只放行一眼看得出安全的」。`SAFE_SEGMENT` 用字元集先收斂，再比對白名單與路徑。這是從黑名單被紅方打穿後改出來的，過程在 `v2-說明.md` 的「紅方找到的繞過與教訓」。
   - 邊界誠實：第 308–310 行自己寫「bash 沒有被真正隔離……不是安全邊界」；`todo_write`、`task` 的 allow 理由都寫在 `check_permission` 裡。
   - 失敗路徑有處理：hook 壞掉 fail-open 但**一定**印警告＋寫 log（第 421 行）；摘要失敗有冷卻（`COMPACT_COOLDOWN_TURNS`）；subagent 的 API 例外轉成該 task 自己的 `is_error`（第 658–664 行），不丟掉同批已執行工具的結果。

2. **問題與改寫**

   - 【選改】`write_file` 的寫入沒有指定編碼（第 193 行 `p.write_text(content)`），而所有讀取都明寫 `encoding="utf-8"`（`_read_text`）。在非 UTF-8 預設編碼的環境（例如部分 Windows）寫入含中文的內容會與讀取不對稱。公開後讀者會在別的機器上跑，這是最容易被面試官指出的小瑕疵。見作業單 C1。
   - 【選改，不改程式只加一句說明】`grep` 的 regex 來自模型，沒有逾時（`re.compile(pattern)` 後直接在每行 `rx.search`）。惡意或笨拙的 pattern（catastrophic backtracking）可以讓整個 harness 卡住，`bash` 有 30 秒逾時而 `grep` 沒有。這屬於「已知限制」層級，建議 README「限制」段列一句，不必在公開前改程式。
   - 【選改，說明用】模組層可變狀態：`TODOS`、`SESSION_ALLOW`、`LAST_USAGE`、`COMPACT_COOLDOWN`、`SESSION_SYSTEM`、`SESSION_MEMORY`、`SUB_COUNT`、`HOOKS`。直接後果是測試的 `env` fixture 要 monkeypatch 十幾個全域（`tests/test_agent.py` 第 30–50 行）。這是「學習用單檔」的合理取捨，**不建議公開前重構**，但面試官一定會問，README 要有一句自己的答案（見「README 內容規格」第 8 段）。
   - 【選改】檔頭 docstring 第 1 行是一長串功能清單，建議不動；但 `SYSTEM_PROMPT` 與所有 `TOOLS` 描述都是**繁體中文**。這不是缺點（見辯論 5：它是實驗變數之一），但 README 必須明說。

3. **事實與邏輯**
   - 程式內數字與敘述一致：`SYSTEM_PROMPT` 說「八個工具」、`TOOLS` 實際 8 個、檔頭 docstring 也寫 8 個、測試 `test_system_prompt_mentions_task_and_eight_tools` 鎖住它。
   - `COMPACT_AT_TOKENS` 預設 8000 的註解（第 25 行）誠實寫了「故意設低讓測驗觸發」。這點在 README 要放大，因為它決定了「v3 完成標準：context 不爆」這句話的含義（見辯論 7）。

4. **與目標讀者的契合**：技術面試官會喜歡錯誤處理與歷史合法性不變量（tool_use／tool_result 配對）。教授會喜歡每個設計決定都有「為什麼」。兩者都需要 README 當入口，因為 964 行單檔對 10 分鐘的讀者不友善。

5. **範圍與語氣**：沒有過度承諾；沒有誇大成「安全」。

6. **定案決定落實**：compaction 整段替換（`compact`）、CLAUDE.md 進 system 並凍結（`build_system`、`SESSION_SYSTEM`）、todo_write 整份取代、subagent 唯讀不遞迴（`SUB_TOOLS` 由 `TOOLS` 篩出、不含 `task`，且有 `test_execute_tool_has_no_task_so_it_cannot_recurse`）、hooks fail-open——全部與程式一致，沒有寫錯。

7. **結論**：小修後可公開（C1 為選改）。

4. **語言。** 程式註解、system prompt、工具描述、所有文件都是繁體中文；計畫的 README 是英文為主。英文讀者進入 repo 後第一個點開的檔案就是中文。處理方式見辯論 5。

**A.3 限制段要列的事實（皆已在文件中承認，只是集中起來）**
